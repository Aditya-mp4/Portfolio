Full-Stack · MERN 🤝 Team project — CodeSquadz

VideoCrypt

A secure video streaming platform with role-based authentication, built end-to-end with the MERN stack — MongoDB, Express, React, and Node.js — alongside a SQL layer for structured user data, as part of a collaborative team.

GitHub 🏢 Read about the internship →

How it works

auth.middleware.js — request pipeline
Client requests a video
→
// JWT decode
role: "uploader"
// SQL lookup
permissions.find(user_id)
// Mongo lookup
video.metadata(video_id)
→
Access granted
Stream begins

What it does

🔐

Role-based auth

Viewer, Uploader, and Admin roles gated behind JWT — each role sees only what it's permitted to.

📺

Secure streaming

Videos are served through protected Express routes, with token validation on every request.

🗄️

MongoDB + SQL

MongoDB stores flexible video metadata while a SQL layer handles structured user and permission data.

👥

Team-built

Delivered collaboratively with a small team — shared repo, feature branches, and integration work.

Why I built this

This one wasn't a solo build, and honestly that's most of why it's interesting to talk about. I built VideoCrypt during my MERN Stack Developer internship at CodeSquadz (AppSquadz) over the summer of 2025, working as part of a team rather than by myself the way most of my other projects go. Read more about the internship itself →

Solo side projects and team internship work are just different animals. On my own projects I can restructure the entire thing on a whim at 1am because a better idea occurred to me. On this one, I had to actually agree with teammates on what the API contract looked like before I touched a line of the frontend, because someone else was already building against it. Dividing up who owned the auth flow, who owned the video upload pipeline, and who owned the React views, and then making all three integrate cleanly, taught me more about real collaborative engineering than any tutorial could.

The technical core that took the most thought was getting role-based authentication to play nicely across two databases at once. MongoDB was the natural fit for video metadata — flexible, schema-light, easy to iterate on. But user roles and permissions felt like they belonged in a proper relational structure, so we brought SQL in alongside it. Keeping a user's role and access rights consistent across both stores, especially once JWTs entered the picture, meant being very deliberate about where the source of truth actually lived.

There's also just a different kind of discipline that comes with an internship deadline versus a personal project deadline I set for myself. When it's my own thing, "done" is whenever I feel satisfied. When it's a team internship deliverable, done means the feature works, integrates with what everyone else built, and ships on time — and that pressure made me a more careful, more communicative developer.

Challenges & learnings

😤 Challenges

  • Keeping user roles and permissions consistent across MongoDB and SQL at the same time.
  • Agreeing on a stable API contract with teammates before the frontend and backend could work in parallel.
  • JWT edge cases — expired or malformed tokens causing silent auth failures on the frontend.
  • Merging feature branches without stepping on code someone else was actively building.

💡 Learnings

  • Middleware-based auth checks scale far better than sprinkling permission logic across routes.
  • A clear, agreed-upon API contract prevents most integration bugs before they happen.
  • Working to a shared deadline builds a different kind of discipline than a solo project ever does.
  • Code review from teammates catches things I'd never notice reviewing my own work alone.
