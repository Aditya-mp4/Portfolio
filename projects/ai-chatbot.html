What it does

🎭

5 distinct personas

Corporate, Friendly, Empathetic, Direct, and Luxury — each with its own tone, vocabulary, and response structure, engineered entirely through system prompts.

💬

Full conversation memory

The chatbot keeps complete conversation history across persona switches, so context is never lost mid-chat.

📊

Session analytics

Tracks message counts and persona usage per session so behavior can be reviewed and improved.

⚡

Zero code switches

Every persona is a prompt, not a build — swapping personality happens through selection, not a redeploy.

Why I built this

What pulled me into this project was a simple question: how far can you actually push a single model's behavior using nothing but instructions? No fine-tuning, no separate models, no code branching per persona — just five very different system prompts sitting in front of the same Claude API call. I wanted to see if prompt engineering alone could hold up under real conversational pressure, not just a one-off demo answer.

The hardest part turned out to be persona "bleed" — the model quietly reverting to a neutral, default tone a few turns into a conversation, especially once things got more complex or the user asked something slightly off-script. I ended up treating the system prompt almost like a spec document: explicit vocabulary rules, sentence-length constraints, and just as important, a list of things the persona should never do. Negative constraints did more work than I expected.

Luxury was, weirdly, the hardest persona to get right. My first instinct was to just crank up the formality — longer words, more elaborate phrasing — and it read as stiff and robotic instead of refined. Real luxury tone is more about restraint and confidence than decoration, and it took a few rewrites of that prompt before it stopped sounding like a thesaurus had taken over the conversation.

QA-ing this thing was its own lesson. Testing one chatbot is one job; testing five personalities layered on the same engine is five jobs happening at once, and it forced me to actually think about what "correct" meant for each one instead of testing a single flat standard of quality.

Challenges & learnings

😤 Challenges

  • Preventing persona bleed — the model drifting back to a default, neutral tone mid-conversation.
  • Balancing strong persona constraints against staying genuinely helpful and accurate.
  • Luxury persona needed careful vocabulary curation — over-formal read as robotic, not refined.
  • QA-ing five personas at once effectively multiplied the testing surface by five.

💡 Learnings

  • System prompt structure matters as much as content — ordering shapes how strongly the model holds a persona.
  • Explicit negative constraints ("never use slang") did as much work as positive ones.
  • Claude's conversation memory made multi-turn context handling straightforward across switches.
  • Session analytics surfaced which personas needed the most prompt iteration.
