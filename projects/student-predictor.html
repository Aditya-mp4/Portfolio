What it does

Data preprocessing

Handles missing values, encodes categorical fields, and scales numeric columns before anything touches a model.

🔧

Feature engineering

Derives new signals from raw records — the kind of features that don't exist until you go looking for them.

🤖

Model comparison

Trains and evaluates several classic algorithms against the same data to see how each one actually performs.

📊

Honest evaluation

Picks a model based on how it holds up on held-out data, not just how good it looks on the training set.

Why I built this

I wanted to sit down and build the classic machine learning pipeline end to end, not just the model-fitting part everyone jumps to. It's easy to call .fit() on a dataset someone else already cleaned for you — it's a different thing entirely to start from a messy pile of student records and get it into something a model can actually learn from.

Most of the real work turned out to live in preprocessing and feature engineering, not in the modeling step itself. Real student data has missing values, inconsistent categorical labels, and numeric columns on wildly different scales — attendance percentages next to raw assignment counts next to grade letters. Getting that into a clean, consistent shape, and then engineering features that actually carried signal instead of just noise, took far longer than picking an algorithm ever did.

Comparing models honestly was its own lesson. It's tempting to just pick whichever one gives the highest number and call it done, but that's not really evaluation — that's just chasing a metric. I paid attention to how each model behaved, not only what it scored: some handled the noisier, more inconsistent features a lot better than others, some needed their inputs carefully scaled first or they fell apart, and some were more stable across different train/test splits than others. That process of actually comparing, not just running one model and stopping, is what made this feel like a real ML project instead of a tutorial exercise.

If I revisited this, I'd want to spend even more time on the feature engineering side — that's where I saw the biggest swings in how well a model could actually generalize.

Challenges & learnings

😤 Challenges

  • Real student data arrived messy — missing values, inconsistent categorical labels, mismatched scales.
  • Deciding which engineered features actually helped versus which just added noise.
  • Comparing models fairly without letting one lucky train/test split skew the picture.
  • Balancing how much time to spend on preprocessing versus modeling itself.

💡 Learnings

  • Preprocessing and feature engineering are where most of the real work in ML actually lives.
  • Different models handle noisy or inconsistent features very differently — worth testing more than one.
  • Evaluating on held-out data honestly matters more than chasing the best training score.
  • Simpler models are sometimes more robust than complex ones when the data itself is imperfect.
